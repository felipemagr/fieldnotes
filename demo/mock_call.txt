# Mock onboarding call, about two minutes: the engineer runs a playbook, the client answers.
# A Spanish consumer lender joining a new facility. Comments say what each answer exercises.

ME: How do you send loan data to lenders today?
# Mapping with a docs link: file adapter -> declarations.
CLIENT: Every month our finance team emails an Excel export from our loan system. We can't change the format, the vendor controls it.
ME: What does the file look like?
# Risks: Spanish date and number formats.
CLIENT: One row per loan, about forty thousand rows. Dates are day, month, year, and amounts use a comma for decimals.
ME: Is it the full portfolio every month, or only the changes?
# Answered: the board should never ask it.
CLIENT: The full portfolio. Loans that are paid off just aren't in the next file.
ME: What happens today when a file has errors?
# Validation (dry_run) and idempotency (external_id).
CLIENT: The lender tells us a week later, we resend the whole file, and some loans get counted twice.
ME: How do repayments come in?
# Stripe -> our webhook intake -> payments/bulk; time-zone cut-off.
CLIENT: Through Stripe webhooks. Our month end is Madrid time, but Stripe reports everything in UTC.
ME: Anything unusual in the data we should know about?
# Questions for the client, and eligibility for Ops.
CLIENT: Some loans have no days past due filled in, and restructured loans keep the same contract number. Do those still count for the facility?
ME: Anything else you need from us?
# Not in the docs (outbound webhook), and commercial for Ops.
CLIENT: Can you notify us by webhook when a submission is processed? And can clean data get us a better advance rate?
ME: I'll come back to you on both. Thanks.
